### 2. 你的统计脚本（实战）

✅ **脚本整体结构**
- 3种统计模式：场景、类型、普通总计
- 输入：A表 + 映射表
- 输出：带颜色标记的Excel统计表

✅ **核心概念理解**
- **链路**：不同的算法版本
- **rawquery vs query**：用户原始输入 vs 标准化
- **A表 vs 映射表**：标注数据 vs 分类信息

✅ **核心指标含义**
| 指标 | 含义 | 你的理解 |
|------|------|---------|
| 有结果率 | 有多少query返回了结果 | ✅ |
| hit_rate | rawquery级命中率（A/B级） | ✅ |
| Agood率 | 文档级的A占比 | ✅ |
| query_Agood率 | query级的A占比平均 | ✅ |
| NDCG | 排序质量（0-1） | ✅ |
| Authority | 权威度（0-1） | ✅ |
| Timeliness | 时效性（0-1） | ✅ |

✅ **关键函数理解**
- `map_relevance_label()`：标签转数字（A→4, B→3...）
- `dcg()`：计算DCG（排序质量的基础）
- `auth_score()`：评估文档权威度（期刊、指南、教科书...）
- `time_decay()`：计算时效性（e^(-0.161×年龄)）
- `run_stats()`：**最核心**，计算所有指标

✅ **常见的坑**
1. 如果列名不对（如"二级场景 "多了空格），会报错
2. 如果时间戳列不叫 `post_ts`，时效性会是0
3. 如果标注是 `"A+"`，会被识别为None
4. 如果不提供映射表，hitrate会变成100%（假数据）
5. Agood率 ≠ query_Agood率（文档级 vs query级）

## 📌 重要提醒

### 学习编程的正确心态

❌ **不要这样想：**
- "我要记住所有语法"
- "我要能从零写出复杂代码"
- "我看不懂代码就是我太笨"

✅ **应该这样想：**
- "我能读懂这段代码在干什么"
- "我能指出这里可能出什么错"
- "我能判断这个结果对不对"
- "我能和AI清楚地描述需求"

### 你的优势（数学背景）

✅ **逻辑思维强**
- 代码就是"用文本写的公式"
- 函数就是"映射"，列表就是"序列"
- 你理解这些概念比纯文科生快得多

✅ **严谨性高**
- 数学训练让你习惯"定义→推导→验证"
- 这正是编程需要的思维方式

✅ **对数字敏感**
- 能快速判断统计结果是否合理
- 这是数据工作者最重要的能力

### 和AI协作的正确姿势

✅ **好的协作方式：**
1. 我给你代码
2. 你逐行理解（不懂就问）
3. 你指出"这里如果数据是XX会怎样"
4. 你验证结果"这个数字对不对"
5. 发现问题时，你能说清"哪一步出错了"

❌ **不好的协作方式：**
1. 我给你代码
2. 你直接运行
3. 看到结果就用
4. 出错了也不知道哪里错
